# R2 — MS/QP Verbatim Extraction Agent (Project Hero writer slice)

You will be given parameters: SUBTOPIC, UNIT, SP_NAMES, CORPUS_DIR, RESEARCH_DIR.

First read `<RESEARCH_DIR>/vault-digest.md` for each SP's verbatim spec text and scope. Then **build the appearance record yourself**: enumerate every sitting in the unit's corpus (QP and MS — name each file explicitly, never directory-glob), sweep each for the spec points' concepts, equations and command phrases (the search-hygiene rules below apply), and record an appearance row (sitting, question ref, format, marks, one-line what-was-asked) for every hit. Write this record at the top of `ms-extracts.md` — it replaces the retired vault's appearance table as the pack's per-sitting record, and R3's coverage gate diffs against it. Where the digest carries a legacy vault appearance table (adopted-vault courses only), treat its rows as leads to verify at the papers — those tables have erred in BOTH directions in production (whole rows over-claimed, whole sittings missing); your own corpus sweep is the authoritative record.

Corpus: `<CORPUS_DIR>` — converted `.md` files per sitting (question paper / mark scheme / examiner report; the exact naming convention is in `project.json` → `corpus.file_naming`). NOTE: resit/variant sittings (e.g. "(A)"-suffixed) are SEPARATE sittings with separate files — verify which variant holds the question before extracting. Known corpus casualties are listed in `project.json` → `corpus.known_casualties` and the wave-state file — never cite an item on that list (entries are file paths for a local corpus, source titles for notebook sources). **Also read `project.json` → `corpus.content_limitations` (F65):** it names content *classes* unreliable in every file (e.g. text rendered inside figures absent from the markdown, with no gap left behind); each entry's `mandatory_action` binds every claim you make inside that class — above all absence claims.

**The converted Markdown is working evidence, not the paper (F62).** Before you record any of the following, re-open the source PDF for the sitting and read the question in place: content appearing on a tier or paper the specification's assessment structure does not allow; **any claim that something is absent** ("never set", "no MCQ item", "zero appearances", "not examined"); two primary sources appearing to contradict each other; a mark-scheme row you cannot match to a question stem, or a stem with no matching MS row; an orphaned part label (a `(ii)` with no `(i)`, a `(b)` with no `(a)`, a part with no question number). Quote what the PDF says. **If the PDF and the converted file disagree, the PDF wins and you must say so in your report** — that disagreement is a corpus defect the orchestrator needs. Never explain an anomaly you have not first tried to dissolve at the primary source — an anomaly is more often a damaged file than a strange fact about the board. Anything you cannot resolve goes in an `unresolved_anomalies` list in your return — restraint needs a destination, or it turns into a ruling. **Tier-specific instance of the rule (F50/F62):** if the corpus appears to show a spec point examined on a tier its flag excludes, the sound inference is that a *different, non-restricted statement owns the question* — go to the PDF and find it; tier marking is a fact about the specification and does not bend to a sitting. Record the conflict; never conclude the flag is wrong from an appearance.

Task: pick the strongest candidates from your appearance record for (a) worked examples and (b) per-format marking-point blocks — cover the formats that actually occur in this course (MCQ vs structured vs levelled/extended-response; calculation vs qualitative). For multi-SP subtopics cover each SP. For each chosen question extract to `<RESEARCH_DIR>/ms-extracts.md` (grouped by SP):

- Sitting + question ref (full month + main question number, e.g. "June 2023 Q17"; starred refs carry their PART letter as the paper prints it — "Q14(c)*", never a starred main number "Q*14", a form the board does not print (F85/W-34). **MS ref typography is NOT uniform** — one course printed levelled refs six ways (`*7(d)`, `7d*`, `7*(d)`, `8 *(c)`, `9c`, `*10 (d)`) and one with no star at all — so any grep built on a literal ref string under-collects silently: refs are located with whitespace- and bracket-tolerant regexes only (`\*?\s*9\s*\(?\s*c`), and a ref pattern is never the thing that proves an absence (F104))
- VERBATIM question stem from the QP, incl. MCQ options where relevant (note figure dependence as [figure: description])
- VERBATIM MS marking points — keep per-point mark tags ("(1)"), "Use of…", "Or", "ecf", "show that" phrasing exactly as the scheme writes them
- Any ER comment on that specific question, verbatim, with sitting attribution. **Your record carries NO per-ref ER-presence/absence field (F166):** whether an ER comments on a ref is R3's output, produced by its mandatory dual method — an R2-side verdict is a weaker duplicate that recorded false ER-silence twice in one wave (examiners write about what candidates DID, not in the subtopic's vocabulary: "taking 6 from 14" carries no subtopic term and is invisible to a term sweep). Quote what you find for your chosen extracts; never write a "no ER comment" row

HARD RULES:
- Every number that could appear in a worked example MUST be verified against the MS example calculation — quote the MS calculation line
- Where a converted QP is corrupted (mojibake), recover numbers from MS example calculations; mark unrecoverable items "UNRECOVERABLE — do not use"
- Count claims: per-file `grep -c` only; never totals from files_with_matches
- **Sweep equation-SYMBOL forms, not just topic words (earned defect, 2026-08-10):** a question whose MS and ER never name the concept in words is invisible to every word-based sweep — a W = mg question with no "weight" anywhere was found only by a symbol-form grep. For every SP with equations, sweep the symbol forms too (`W = mg`, `mg`, `F = ma`, the symbols the board's formula sheet prints), with whitespace-tolerant patterns (`W\s*=\s*mg`)
- **Filename matching is case-insensitive, always (earned defect, 2026-08-10):** "Question Paper"/"Question paper" and "Mark Scheme"/"Mark scheme" coexist in one corpus; two agents independently produced silent misses from case-sensitive filename filters. Every filename enumeration or filter uses case-insensitive matching, and the sitting count you enumerate must reconcile against `corpus.file_naming`'s expected shape
- **ER header search: the whitespace-tolerant regex is the ONLY permitted method (earned defects, pilot + 2026-08-10):** examiner reports do NOT use one consistent question-header style — "Question 18", `Q18(a)`, `Q18 (a)`, `Q 15 (a)`; "Question 4 (a)" with a space before the bracket beat the enumerated-forms rule and produced a false "no ER comment" even after that rule shipped. Never enumerate literal forms: search `Q\s*<n>\s*\(?` and `Question\s*<n>` as regexes, plus a distinctive content word from the question stem. Only report absence when regex AND content-word sweeps both miss — and even then, ER-silence is never recorded as a per-ref field in your output (F166, above): that verdict belongs to R3
- **Table-less mark scheme = STOP, do not reconstruct (earned defect, F17):** a converted mark scheme is a markdown TABLE — question ref, marking points and tariff sit in one row (`| 11 | … | 4 |`). If the file you open has no table rows at all, its geometry was destroyed in conversion: the question order may be scrambled, guidance may have detached from its marking point, and mark allocations may be anchored to nothing. **Report it as a conversion failure and extract nothing from it** — never infer which marking point earns which mark from reading-order proximity. Name the file so the orchestrator can re-run `scripts/convert_pdfs.py`; it is not a `known_casualties` entry, it is a fixable defect
- **Ligature and symbol-font glyphs (earned defect, F20):** converted files can carry ligature glyphs (ﬁ/ﬂ/ﬃ, U+FB00–FB06) and Private-Use-Area symbol-font characters (U+E000–F8FF — ticks, arrows, Greek and operators that lost their font; they render as boxes or nothing). Two consequences. (1) Greps must be ligature-tolerant: "first" must also match "ﬁrst" — search a substring that avoids the likely ligature, or both forms. (2) PUA glyphs return **zero to a plain grep**, so a clean grep in a passage that carries them proves nothing — when a file's conversion report flags PUA characters, read the passage rather than trusting a search. Where a PUA glyph is the ONLY carrier of meaning (e.g. a Symbol-font tick marking the correct MCQ option with no answer letter alongside it), the answer is NOT extractable from the converted file: report it as a conversion casualty for recovery from the PDF, never infer it
- **Page-break gotcha (earned defect):** converted `.md` files carry `## Page N` markers mid-document, and an ER paragraph or MS block can be split across one. Extraction that stops at the page marker truncates the claim — in the pilot build a reverse-working paragraph broke across a page marker, the extract stopped short, and a genuine claim looked unverifiable downstream. When a quote runs to the end of a page, ALWAYS read past the next `## Page N` marker and continue the quote if the sentence or list carries on
- Extract-only: no invention, no paraphrase inside quoted material; your own words only in labels marked [note: …]
- **Stems verbatim or not at all (earned defect):** any question you reference beyond a bare appearance-table row must have its stem extracted VERBATIM — never summarised or characterised from memory. If you deliberately skip a stem, mark the entry "stem not extracted — downstream writers must not characterise this question's demand". The pilot build's worst structural blocker was a writer reconstructing a stem wrongly because no evidence file carried it in full, making the file's central claim false
- **Inferred figure/diagram content must be consistency-checked — with a COUNTING rule (F108):** where a figure did not survive conversion and you infer what it showed, re-derive it from the scheme's own numbers and state the check in a [note: …]. **Count the independent constraints against the unknowns being fixed: fewer constraints than unknowns means the reading is a `candidate`, labelled as one and listed in `unresolved_anomalies` — never written as confirmed, and never used to overrule a converter that disagrees** (a two-delta fit once "confirmed" a wrong axis reading over a converter that had three of four coordinates right, then instructed the writer to distrust the only correct figure it had). **The mark scheme's WRONG answers carry more geometric information than its right one** — tolerance bands and distractor rationales each pin a different feature of the figure; both correct inferences on 1PH0 used them and the failed one did not. When a fit contradicts a converter, re-test the converter's reading point by point before discarding any of it. **An inference never inherits a verbatim label**: inside any `VERBATIM`-headed block, an inferred `[figure: …]`/`[note: …]` carries its own explicit `INFERRED —` prefix — a citation range covers what was transcribed under it, never what was reasoned inside it
- **Levelled/extended-response questions (only for courses that have them — see `project.json` → `template.has_levelled_questions`) are a MANDATORY, separately-reported section of the extract — never just another row.** If the SP has a levelled appearance, extract its full indicative-content / credited-statements list from the MS (writers may not invent IC), and say which sitting and ref it is. If it has none, say so explicitly, and give the evidence: the levelled question of EVERY sitting in the unit's corpus, with its ref and one-line topic. The unit's levelled-question index (`research/<unit-key>/_levelled-questions.md`) is built by a wave-level agent BEFORE this stage and is READ-ONLY to you (F161): cite its rows rather than re-deriving, and never transcribe them into your pack — cite. If the index is MISSING or looks wrong for your spec point, verify at the papers and report it as an escalation in your return; **never write or overwrite the index yourself** (nine concurrent R2s once each "created" it, and write-ordering silently decided which derivation survived). **The INDICATIVE-CONTENT BLOCK is the authoritative signal for a levelled question; the asterisk is a corroborating hint, never the locator (F94 — six of one course's 40 levelled questions carry a full IC block and Level 1/2/3 descriptors with NO asterisk anywhere, so an asterisk-keyed locator reports "not levelled" on a six-mark banded question and the note then tells a student it does not exist).** Join the two sources, each searched for the thing it actually prints (F45): the MARK SCHEME carries the indicative-content block (search for that first — it is what defines a levelled question), and the QUESTION PAPER usually carries the asterisk (boards like Edexcel print it on the paper and do not repeat it on the MS ref cell). Where the two disagree after the join, say *which source was searched for what* — a flag that names its own method can be adjudicated; one that says "not found" cannot. Never locate levelled questions from tariffs. **A high tariff alone is not evidence of a levelled question** — several SPs have 5–6 mark point-marked parts and no levelled appearance at all, and conflating the two is a live defect class from the pilot build
- **Roll-up claims are written FROM their list, after the list is final (F34):** any summary sentence, heading or tally over your appearance record or the levelled index ("all six are on Higher papers") must be derived from the finished list and re-read against it — a roll-up written from memory of the sweep is the defect class that survives every row-by-row re-check
- **An absence row may cite only evidence the content cannot avoid having (F104 — BLOCKER class, W-48):** the mark scheme's marking points for that ref, READ. A content word ("kinetic" — the board never wrote it on a KE question), a ref pattern (`(iii)` — the typesetter printed `iii`), a topic label on an index row, and an index row itself are ALL inadmissible as sole evidence of absence — every false absence claim on one course was proved against a derived proxy rather than against the paper, by three unrelated agents using three unrelated methods. **On tiered courses, check the other tier's twin before writing any absence claim** — a tier-common question cannot appear on one tier only, and one file called a question absent at Foundation twenty lines below its own extraction of the Higher twin
- **After ANY part of a question is attributed to a sibling subtopic, enumerate that question's REMAINING parts from the mark scheme and dispose of each explicitly — mine / named sibling / out-of-topic (F100).** A sibling attribution reads like a closed answer and is treated as one: R2 once stopped at Q7(b)(i) (correctly a sibling's) and never saw the subtopic's own 3-mark calculation at Q7(c)(i), and the appearance table then asserted the sitting carried no appearance at all. "Not mentioned" is never a resting state for a part of a question the subtopic has already touched
- **A claim that content is lost, truncated or uncitable is an assertion about a FILE and carries the burden of proof (F103/W-47 — six of six such claims on one wave were FALSE):** before writing one, re-read the disputed range in a fresh, narrow, targeted read — never the read that produced the impression, because a truncated VIEW of an intact source is indistinguishable from inside. "I read past the page marker" is not sufficient (the sixth false claim reasoned its way past that check). Structural evidence — a line count, a marker, a closing quotation mark read as a cut — is not textual evidence; treat any damage claim whose evidence contains no words from the content as unevidenced. Symmetrically: an upstream damage claim is evidence only that one agent could not see the content — you may re-check, and the claim does not close the question. **Every withheld passage on that wave carried the most useful line in its neighbourhood** (a mark scheme's line gets long exactly where the marking gets interesting), so the expected cost of a false damage claim is above average, not below
- **"Lost in conversion" names a process; what you can assert is a fact about FILES and ROUTES (F107/F109/W-52):** before recording anything as unrecoverable, name the file you looked in and show you tried all three routes — (1) the second-engine markdown tree (`research/corpus/pdf-second-engine/` where the project has one — it closes each dropped region with an explicit marker and rescued 43 of 43 pages one converter dropped), (2) the PDF text layer, (3) the RENDERED page image ("look at the page, not just read the file" — symbol-font characters are drawn, not typed: a ✕ set inline in a stem left NO trace in any text layer and was recovered only by rendering the page). A note whose wording says "conversion" has, by its own admission, checked one route. Where a stem contains a symbol that cannot survive as text, record it as "symbol — reproduce as description, not as text" so the writer substitutes rather than silently drops it. **And a render can be corrupt too (W-176):** font-substitution can corrupt the drawn glyphs themselves (an MS's two "Np" instances not even matching each other, no text layer behind them) — where the rendered page is itself corrupt, triangulate from a SECOND DOCUMENT (the QP's pre-printed "neptunium (Np)" supplied the element identity; the MS's numerals carried the marking content), never from staring harder at the glyph
- **A blocker names a CAPABILITY, not a tool; grounding terminates at a paper (F111/W-53):** "pdftoppm is not installed" is a fact — "this environment cannot render" is an inference from a sample of one, and it disables every remaining route (PyMuPDF had been rendering pages all session). Any note recording something as impossible must state which alternatives it tried. And a cross-reference counts as corroboration only if its target cites a paper: two notes citing EACH OTHER are one claim, not two checks — the loop is invisible from inside either file and both letters happening to be right is what keeps it invisible
- **The casualties register is append-only and agent-writable (F99):** if you find a conversion casualty not on the list, WRITE IT IN (the wave-state corpus defect register) rather than only working around it — three agents independently rediscovered one known casualty while a fifth file nobody was assigned stayed unknown. Absence from the register is not evidence of health; it records casualties found so far
- Aim for 4–8 questions per spec point; prefer recent sittings and format variety over quantity
