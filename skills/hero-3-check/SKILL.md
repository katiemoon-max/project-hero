# /hero-3-check — checkers, rulings, fixers

Read `project.json` and the wave-state file. Checker model: strongest available per project policy (never below Opus 5). Fixers: research tier (default Sonnet).

## Per drafted subtopic

1. **Checker**: "Follow ALL instructions in `prompts/CHECKER.md`" + parameters, including EXTRA_CHECKS assembled from the wave-state file (cluster boundaries, named exclusions, ref lists for the tariff-coverage rule — the more specific the brief, the more real defects surface). EXTRA_CHECKS are **directed attention, never deletion orders**. **When an EXTRA_CHECK restates an upstream finding, preserve its exact shape (added after Unit 6 wave 1, 2026-08-04):** a NON-CONTIGUOUS list of sittings must never be rephrased as a continuous window ("the six-sitting gap Jun 2022–Oct 2024" for what was a six-item list helped seed a false continuous-gap claim in a draft — Significant Figures B1). Quote the list as a list, or point at the pack line rather than paraphrasing it. **An EXTRA_CHECK sourced from an upstream finding goes stale silently (F47):** it must carry the finding's id AND the state it described ("F37, as of the draft at <date>; verify before acting"), and must be **re-read against the current file before it is passed down** — on 1PH0 both of one file's EXTRA_CHECKS described defects already fixed in an earlier pass, and one, taken on trust, would have "corrected" verbatim board text. **A ruling passed into any brief carries its evidence, not just its conclusion (F57):** if a CAUTION says "do not print X", it says *why*, with the source, so the agent can check the reasoning rather than enforce it — and a ruling that **overrides a stage-0 data artifact is marked contestable** in the brief, never stated as settled fact (the word "ratified" turned three independent gates into enforcers of one wrong ruling). Where `sp-mapping.json` carries duplicate-SP groups (`primary_id` + `alias_ids` — F15), tell the checker which alias ids the note serves: an alias id covered by the group's single note is **written, not missing** — never report it as unwritten.
2. **Adjudicate escalations — by reading the paper.** When a checker disputes a pack rule, an EXTRA_CHECK, or another agent's claim: the QP/MS text outranks every derived file and every orchestrator instruction. Never average two agents. Record each RULING in the wave-state file with the paper evidence. When a blocker traces upstream (digest/ms-extracts/nlm-check), correct the pack at source with a dated bracketed note — never inside verbatim quotes. Two hard rules on rulings themselves:
   - **To overturn a stage-0 data artifact, show the primary source saying otherwise — never an inference from the corpus (F56).** A ruling made by the orchestrator has no downstream agent with standing to question it, so the burden of proof sits at the point the ruling is written. The specific banned inference: *content appeared on paper X, therefore the tier/level designation is wrong.* Tier is a fact about the specification and does not bend to a sitting — a surprising appearance is evidence that a **different statement owns the question: re-open the source PDF and find it (F62)**; on 1PH0 the "anomaly" was a truncated file, and the wrong ruling turned five independent gates into its enforcers (F57)
   - **A ruling that establishes a CLASS fact triggers a back-sweep of every master in the wave (F51)** — not only the file that raised it. A class ruling with no back-sweep is a ruling applied to the artefact that happened to surface it (1PH0: a starred-refs ruling corrected the derived index and no gate noticed the knowledge files for two weeks)
3. **Fixer**: "Follow ALL instructions in `prompts/FIXER.md`" + the checker report + any orchestrator rulings (including "do NOT apply finding X" where overruled). **Before launching fixers, commit the checked masters** — the diff sweep at step 4 and the fixer self-report check both need the pre-fixer baseline (F63/F66). **Never hand-edit a file a fixer is concurrently working on (F66)** — the fixer cannot tell its own edits from yours and will report yours as its. Fixers report per-item application; chase any item reported unapplicable — but **the completion check is independent of the fixer (F53)**: after every fixer returns *or dies*, grep the master for each finding's offending string (present ⇒ unapplied) and its correction (absent ⇒ unapplied). A fixer that dies after editing looks exactly like one that never ran — no report, no `## Fixes applied` section, file fully fixed — and the fixer step is **not idempotent**: a dead fixer is never blindly relaunched; verify what landed first, then dispatch a fresh brief covering only the remainder.
4. **Fixer-diff re-sweep**: `scripts/fixer_diff_sweep.py` on every fixer-touched master — scans only fixer-ADDED lines (git diff) for manufactured-certainty patterns and new quoted spans. Report-only on hits; orchestrator eyeballs each. **`GATE COULD NOT RUN` (exit 2) means step 4 is NOT satisfied — stop and fix the baseline, never proceed (F42/F63):** on 1PH0 this gate printed "clean" on every fixer-touched file of the build because the project had no git repository, and the one regression it existed to catch had to be found by hand. This gate exists because a fixer once introduced a false absolute claim after checker sign-off, and it shipped.
5. **Sampled blind re-audit**: after the wave's fix cycle, 2–3 files (risk-picked: dense sibling clusters, inferred figures/diagrams, calculation-heavy) get a fresh checker pass by an independent agent, blind to `checker-report.md`, writing `re-audit.md`. **Blindness must extend to contested rulings (F57):** the re-auditor is blind to the first checker's report but reads the wave-state file, which is where rulings live — so a wrong ruling reaches it as settled fact and the re-audit becomes a second signature on the first opinion, not a second opinion. Withhold contested rulings from the re-audit brief (let it reach its own answer), or pass the ruling's *evidence* rather than its conclusion. Findings go through the normal ruling → fixer → diff-sweep path. Calibration: pilot build ~10 actionable findings per re-audited file, yield independent of the original checker's model; **corroborated on 1PH0 wave 1 at 13.3 per file, with every sampled file carrying at least one BLOCKER its original (signed-off, Opus 5) checker missed** — the blind pass's yield comes from blindness, not model tier, which is an open structural question for the course owner (F55: if blindness is the active ingredient, the lever is making every check blind, not buying more second passes).
6. **Wave-wide tier/level sweep — a real gate before publish, wherever the course has per-SP tiers (F50/F56/F57).** Sweep every master for tier-bearing language and check each hit against the mapping's tier flag (adjudicating `"partial"` statements at the spec PDF's font spans); require each restriction claim to name its evidence. **Sweep both directions:** wrongly-present restriction language AND wrongly-absent restrictions — an affirmative "both tiers set it" on a Higher-only SP matches no restriction-language pattern, which is exactly how the one real defect passed a restriction-only sweep. *A sweep for the wrong thing being present is not a sweep for the right thing being absent* — apply that test to every mechanical gate you write.

## Wave-state bookkeeping

- **Mark the grid as it happens, never at wave end (F52):** `C` complete when the checker report lands, `F` when the fixer's completion is *verified* (step 3's independent check, not the fixer's say-so), `!` on any escalation — per subtopic. The grid had no owner for these columns and rotted while `/hero` printed it as the course's status; the failure mode is re-running 17 fixers over already-fixed files, which is not idempotent. Better still, derive before trusting: `C` = `checker-report.md` exists · `F` = it contains `## Fixes applied` · `S` = the subtopic id is in `upload-manifest.json` — and where a cell disagrees with the disk, the disk wins and the disagreement is reported
- Blocker/fix/note counts per file, **read from each report's machine-readable `hero-metrics` comment (F49)** — `CHECKER.md` now fixes the item schema (one item per instance, `### [B|F|N]<n> — …`) precisely so this tally can be built mechanically; five schema-free agents produced five schemas and the wave's counts moved by 20% depending on who parsed them
- **Blocker-class tally over SEVEN classes (F48):** manufactured certainty, quote integrity, factual/data, symbols, direction, **process leakage** (production-process language in student-facing prose — CHECKER item 14 already finds it; the ledger just never had the slot), **structural/template** (undefined flagged terms, swallowed labels, skeleton breaks — items 4/12). Anything genuinely outside all seven goes in an explicit `other` slot, itemised, never rounded into a neighbour. **The class tally must sum to the blocker total; if it does not, the class list is wrong, not the count** — this one reconciliation rule surfaces a missing class on the first wave that hits it. This is the metric record that process reviews depend on: a corrupted count is indistinguishable from a right one six months later
- The checker MODEL per file comes from each report's `hero-metrics` line — the agent's own attestation, because the orchestrator can only attest what it *launched*, and session-kill substitutions are exactly the case that matters (14 of 17 1PH0 reports recorded no model, so the "never below Opus 5" policy could not be evidenced for 82% of the wave)
- Any `unresolved_anomalies` from checker reports (F62) must be cleared by adjudication at the source PDF before the wave proceeds to publish
- As the wave's check cycle closes, write completion back to `project.json` → `status` (stage + any blocker left open) — every stage writes its own completion, or the declared source of truth goes stale (F30)
