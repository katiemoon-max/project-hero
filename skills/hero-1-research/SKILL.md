# /hero-1-research — wave research (R1 → R2 → R3)

Read `project.json` and the pipeline blueprint `WRITER-SLICE.md` in the project directory first. One wave ≈ 15 subtopics (max ~19). Concurrency cap per project.json — queue and feed on completion notifications.

**Preconditions:** `project.json` → `structure.ratified` is dated, `paths.corpus_root` points at real content, and the stage-0 evidence artifacts exist: `sp-mapping.json`, `paths.skills_map` and `paths.cobalt_content` (each either a real file or null with a dated ruling). R1 and R2 run unconditionally in every research mode — `research_mode` switches R3 only. If any input is missing, STOP and send the user back to `/hero-0-setup` — an empty evidence brief makes every downstream gate pass trivially, so running anyway fails silently, not loudly.

**Before anything reads `paths.cobalt_content`** (every wave, not just the first): run `python scripts/merge_cobalt_shards.py <project_dir> --check` — non-zero means a shard is newer than the merged file, so re-merge before launching R1. A shard corrected after the last merge otherwise never reaches research, and every reconciliation count passes on the stale file (F23).

**There is no vault stage.** R1 assembles each subtopic's grounding brief directly from the stage-0 artifacts; exam-appearance, examiner-report and mark-scheme evidence come from R2/R3 at the papers — which were always authoritative over the retired vault layer (its appearance tables and ER attributions erred in both directions in production).

**Legacy vaults (adoption path):** where a pre-existing per-SP vault exists for the course (built before the vault stage was retired — e.g. the Edexcel IAL Physics vault), adopt it here instead of ignoring it: profile two notes against R1's nine sections, record `vault: {status: "adopted", path, coverage_profile}` in `project.json` (reconcile filenames onto `sp-mapping.json` with `scripts/build_mapping.py` if they don't match the naming convention), and R1 runs `prompts/R1-vault-digest.md` against the notes instead of the assembly variant. Vault content is leads to verify at the papers, never ground truth.

## Entry gates — first run per course only (before wave 1)

1. **Corpus conversion complete AND all conversion gates verified.** `corpus.conversion.status` must be `complete`, `corpus.known_casualties` current (including any legibility failures from the conversion report — F32), and **`corpus.content_limitations` populated or explicitly empty (F65)** — a content-class limitation recorded anywhere else is a note nothing enforces. Waves must never start against a partial corpus — R2's discovery sweep and R3's ER sweep both assume every sitting is greppable. **Also confirm `corpus.conversion.table_gate_passed` is true**, and if the corpus predates that field (or was converted outside the pipeline), run `python scripts/convert_pdfs.py <corpus_root> --verify` here and read the verdict yourself. A mark scheme that converted to zero pipe characters has no table left: R2 will quote it confidently and be wrong about which marking point earns which mark (F17). Partial corpus fails loudly; a table-less one does not.
2. **Template check (hard gate).** Open two recent QPs and MSs from the converted corpus and confirm the paper structure (MCQ section? structured questions? levelled/indicative-content questions?). **Record the ratified skeleton in `project.json` → `template.exam_skeleton`, fill `has_levelled_questions`, and get both ratified by the user before wave 1.** A high-tariff question is not evidence of a levelled question, and a practical paper may have no MCQ section at all — template assumptions imported from a previous course silently corrupt every file in a wave. Every `template.*` value must come from this evidence, never from the worked example in the repo's README-template. If any sitting can only be reached through NotebookLM, the retrieval evidence bar is higher: at least four papers, QP and MS both, front cover quoted verbatim for totals/timing — and **no superlative ("highest tariff", "only", "always") enters the skeleton without paper-level confirmation**.
3. **Exemplars.** Two style exemplars max (approved pilot + one structural match). A brand-new course has none of its own yet — the first wave's pilot subtopics (see `/hero-2-write`) become the exemplars after the user approves them, and the pilot itself anchors on the pack's reference exemplars in `templates/exemplars/` (F33 — register and depth only; the course's template rules win on form).

## Steps

1. **Create `research/<unit-key>/_wave<N>-state.md`** from the previous wave's structure: model mix line, per-subtopic stage grid (R1|R2|R3|W|C|F|S), SECTION/TOPIC/ids from `sp-mapping.json`, multi-SP SP_NAMES tables, and — before anything launches — confirm the previous wave's "upstream pack corrections owed" list is empty. **Wherever the wave-state file restates a prompt rule, QUOTE the prompt verbatim with its file and line — never paraphrase (F68).** The wave-state file is the working memory and outranks the orchestrator at read time, so a paraphrase that drifts becomes the enforced rule: on 1PH0 both wave-state files paraphrased WRITER.md's no-skills rule as its exact opposite ("the writer prints the no-skills marker" for "OMIT the line entirely"), and following the wave-state text would have failed a publish gate on a correct wave — and very nearly injected four invented lines into approved files at publish time.
2. **Write sibling-boundary CAUTIONS** for every cluster of adjacent subtopics in the wave (who owns which equation/concept/practical; which siblings are already live and must be cross-referred, never re-taught). This is load-bearing — orchestrator cautions have repeatedly been wrong in production, so word every caution as directed attention that invites escalation, NEVER as a deletion order.
   - ⚠️ **Also name the LIVE documents in ADJACENT TOPICS that share a phenomenon (added after Unit 1 wave 3, 2026-08-03).** Sibling cautions cover the wave's own cluster, which leaves a structural blind spot: four terminal-velocity questions were already owned, with marking points, by a live document filed under a *different topic*, so R2 and R3 could not see it and the collision surfaced only at the checker — the last gate before the user. Before launching R2, search the manifest for live docs whose subject matter overlaps the wave's phenomena (terminal velocity, energy chains, free-body diagrams, graph reading are the recurring ones) and name them in the briefs. **Naming them is collision detection, not an ownership ruling** — a live document's claim about what it owns is an assertion; only the printed scheme decides.
3. **Launch R1 per subtopic** (model: per project.json research tier) — "Follow ALL instructions in `prompts/R1-evidence-assembly.md`" + parameters (paths to `sp-mapping.json`, the skills map, the Cobalt commentary file and the converted specification, plus the notebook id). On the adopted-legacy-vault path, use `prompts/R1-vault-digest.md` instead. Record flag-block rulings (which SPs the skills map marks as having no skills line, per the project's no-skills marker) in the wave-state file as they land. An SP missing from the skills map, or lacking verbatim spec text, is an R1 ESCALATION — fix it at the stage-0 artifact, never paper over it.
4. **Launch R2 per subtopic.** R2 discovers the subtopic's appearances itself: it enumerates every sitting in the unit's corpus, sweeps each QP/MS for the spec points' concepts (the prompt carries the search-hygiene rules — explicit file naming, ligature-tolerant greps, header-form tolerance), records an appearance row per hit, then extracts the strongest candidates verbatim. On the adopted-vault path, the digest's appearance table is a lead list to check — never the universe of appearances (production experience: those tables err in BOTH directions). If the course has levelled/extended-response questions, the levelled-question index for the unit (`research/<unit-key>/_levelled-questions.md`) is built once, by the first R2 wave of the unit, then cited.
5. **R3 after that subtopic's R2 completes — hard gate.** R3's coverage gate silently degrades if R2 hasn't finished (its section 4 becomes a superset, not a gap list). Mode per project.json (`local` is the default):
   - `local` — `prompts/R3-local-check.md`: systematic per-sitting ER sweep, verbatim quotes with file/line refs by construction (kills the NLM-mistranscription defect class). Same output filename/skeleton as the NLM variant
   - `hybrid` — local first; NLM escalation only where a subtopic's sweep returns fewer than ~3 usable ER passages
   - `nlm` — `prompts/R3-nlm-check.md` as written (apparatus gate + coverage gate); for courses whose ER corpus is missing or unconverted (QP/MS corpus still required — its gates verify against local files)
6. **Top up R2** from each R3's section-4 gap list before the writer runs — this gate is also the net that catches anything R2's own discovery sweep missed. Where R3 and R2/digest disagree, the orchestrator reads the paper — never average agents. **The top-up re-verification covers R3's §1 insight attributions too, not just §4 (added after Unit 6 wave 1, 2026-08-04):** for every §1 quote, the top-up agent re-opens the named file and confirms the quoted text sits in the file belonging to the attributed sitting — file identity confirmed from the file's own content, never from the path label. (Where the file's internal identifier is a board placeholder — e.g. Pearson's literal `Publications Code xxxxxxxx*`, which appears in otherwise-substantive files — record "no code published" and confirm identity from other internal content; never invent a code or fall back to the path — F32.) Unit 6 wave 1's worst re-audit catch was a §1 FILE-SWAP (three "Oct 2023 ER" quotes were June 2023's text at identical line numbers) that survived checker + fixer + harmonisation precisely because the top-up gate covered only §4. **And where R3's §1 states a COUNT of sittings sharing a marking-point phrase, the top-up must grep that phrase across ALL the unit's mark schemes — never just re-verify the listed refs (added after Unit 6 wave 2, 2026-08-04):** two §1 counts verified "clean" ref-by-ref were still wrong as counts (a "six sittings print no-unit" claim was really fourteen; a "12 of 13" refrain was 13 of 13) — re-verification confirms presence, only a fresh sweep confirms the count.
7. Update the wave-state grid as each stage completes. Record every ruling inline — the wave-state file is the working memory. Any `unresolved_anomalies` reported by R2/R3 (see the standing anomaly rule in those prompts — F62) must be **cleared by adjudication at the source PDF before writers launch**: restraint needs a destination, or it turns into a ruling.
8. **Closing act of WAVE 1 ONLY — board-conventions extraction (F29, placement ratified as F31).** The extraction is the *exit* step of the course's first research wave, not an entry gate and never `/hero-2-write`'s job: `/hero-2-write` only **asserts** `paths.board_conventions` and refuses to run while it is null. Why here: the extraction reads local files only (spec, mark schemes, examiner reports), so it can never be blocked by an expired MCP token and depends on no wave's output; it is course-wide, so it must not sit inside a per-wave loop needing an "already done?" state check; and the corpus is warm — this wave just grepped exactly these files. Launch "Follow ALL instructions in `prompts/BOARD-CONVENTIONS.md`" + parameters, then **write `paths.board_conventions` into `project.json`**. The wave-1-only label is deliberate and lives here in the skill text — an inferred once-only step gets re-run. (Context: the defect this closes is *uniform* absence — writers run fine against a missing path and each re-derives the conventions alone, so sibling documents describe one marking mechanism three different ways. Patchy absence means an agent slipped; **uniform absence means the orchestrator owes the artifact** — apply that heuristic at every wave close.)
9. **As the wave's research closes, write completion back to `project.json` → `status`** (`stage`, `units_complete`, `next_unit`, any blocker knowingly left open — F29's null path was exactly such a blocker). The wave-state file stays the detailed working memory, but `status` is authoritative-by-declaration: a session that follows the stated rule (read the wave-state file) is fine, a session that follows the stated architecture (trust `project.json`) is misled — so keep both true (F30).

Next: `/hero-2-write` once a subtopic's pack is complete (drafting may begin per-subtopic; no wave-wide barrier).
