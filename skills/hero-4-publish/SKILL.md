# /hero-4-publish — sweep, hold, upload

Read `project.json` and the wave-state file. Upload agent: research tier (default Sonnet). **`createDocument` has no delete or move — never create twice; fixes to live docs go through `updateDocument`.**

**Duplicate-SP groups** (`primary_id` + `alias_ids` in `sp-mapping.json` — F15): one note serves the whole group, but **every Cobalt id in the group still exists and still needs publishing** — the upload must satisfy the primary AND every alias id, and manifest/parity counts are per group, never per primary alone.

## Gates (in order, all mandatory)

1. `scripts/protect_starred_refs.py` on the wave's masters (bold Example labels so a ref's asterisk cannot break emphasis; refs stay UNESCAPED and PART-FORM — `Q16(c)*`, never `Q16(c)\*`, and never a starred main number `Q*16`, F85/W-34), **then `scripts/verify_starred_refs.py` on the same roots (F90 — the verification counterpart was in the pack and wired into nothing):** it flags the defective `Q*n` form, render-checks the part-form refs, and its **exit 2 means the step is NOT satisfied** — same semantics as the diff sweep. On waves known to cite levelled questions, pass `--min-ref-lines` with the expected count so a zero-match run reads as "did not run", not "clean" (F85)
2. `scripts/preflight_sweep.py` on the masters — fix every FAIL (U+1D400 chars, **Private Use Area chars (F97 — invisible symbol-font glyphs; any PUA character in a knowledge file is a blocker)**, escaped refs, \Delta, $c{, images, links, flag-block parity); review every Oxford-comma candidate, every unverified-claim-vocabulary hit (F109/F111), every unbounded-quantifier hit (F120) and **every no-paper-reference worked example (F150 — an unreferenced example may be a faithful reworking or an invention, and nothing but the papers can tell the difference: adjudicate each against ms-extracts.md)**. Then **`scripts/rn_derived_sweep.py` on the same masters (F148/F149 — non-blocking shortlist, human adjudication mandatory):** it flags sentences asserting marking behaviour under an unbounded quantifier whose block carries no paper reference. Do NOT sweep by textual overlap with `rn.md` — paraphrase drops RN-derived content to 0.000 5-gram overlap, so an overlap sweep returns a clean bill of health on exactly the defect being hunted. Test each hit against `ms-extracts.md`: a marking claim no scheme in the pack performs does not ship, however well-formed (on 1PH0 one such claim generalised an rn.md passage the corpus's schemes contradict two-to-one, and passed all six form gates)
3. `scripts/strip_for_cobalt.py` → `.cobalt.md` — pass the wave's masters (or their directory) in ONE call; each writes its own `.cobalt.md` sibling (2026-08-10: the old `[src, dst]` positional shape silently clobbered a verified master on a multi-file call, and the script now refuses any destination that is not `.cobalt.md`). Then `preflight_sweep.py --cobalt` (adds callout/blockquote checks)
4. Validate the skills-line total (the `template.skills_line_label` count) against the wave's OWN skills-omission ruling list in the wave-state file — **derive expectations from the wave's files, never from a handover**
5. **Spec-coverage gate (F60 — BLOCKING).** No wave ships while a spec statement allocated to one of its subtopics is quoted nowhere. Coverage is the **union over every file quoting the statement** — statements are legitimately spliced and merged across subtopics (1PH0's 2.23 lives half in `Newton's Third Law`, half in `Conservation of Momentum`), so a per-file check both false-fails the splits and misses a statement written nowhere. Two checks: **(C) coverage in full** — every content word of the statement's authoritative text appears in the union of its quotes; **(D) wave completeness** — no statement allocated to an already-written subtopic is unquoted (a statement no writer was ever launched for is invisible to every other gate, because nothing else holds the denominator). Implementation: `scripts/spec_coverage_gate.py --stage publish` (in the pack, production-tested on 1PH0 — read its docstring's per-course checklist for the ID grammar and tracker columns). **`--stage publish` exits on the C/D half only (F145):** checks A/B are setup-time and have their own gate at `/hero-0-setup` — a conflated exit meant a course carrying known, accepted setup-time findings printed `GATE FAILED` forever at publish, which teaches the orchestrator to read past the verdict; the verdict line now names which half failed, and a NOTE about the other half is informational, never a licence to skip reading it. Its parser handles **multi-statement quote blocks** (further statements on bare continuation lines below the `> **Specification:**` header; a header-only parse reports written statements as unwritten and sends a writer to duplicate existing work) and **id-less continuation lines (F144 — enumerated statement items: `> a an object projected upwards…`. The pre-F144 parser silently discarded them, so check C had never actually tested any enumerated statement's items on any course, and FAILED a correct document quoting statement 3.5 in full)**, and it prints `PASS` explicitly on an empty gap list — never nothing
6. **Content-limitations gate (F65 — BLOCKING).** A non-empty `corpus.content_limitations` with no corresponding mitigation recorded in the wave-state file blocks publish. A limitation with no enforcement point is a note, not a control — 1PH0's figure-text loss was recorded at stage 0, in writing, with the correct remedy attached, and shipped a defect anyway because nothing read the field. **The mitigation POINTER must resolve (F147 — F65's own failure mode, one level up):** each entry's `ruling` field cites a ruling id, and checking only that a citation is *recorded* passes a dangling or wrong-target citation exactly like a correct one (1PH0's row-loss limitation cited `W-55`, which resolved to an unrelated tier ruling; the real mitigation existed under another number and the gate could not have told either way). Mechanically resolve every cited ruling id in the wave-state file — a citation that does not exist there is a BLOCK; whether the resolved ruling's *meaning* actually mitigates the limitation is the human half, checked at the hold
7. **HOLD — the user spot-checks a sample.** No upload without explicit approval this wave.
8. Upload sequentially via `createDocument` (`.cobalt.md` content only); append every `document_id` + chunk count to `upload-manifest.json` and the wave-state table, **and mark `S` in the wave-state grid per subtopic as each upload lands (F52 — the grid's columns each need a named owner, and this stage owns `S`)**; zero-warning uploads are the norm — investigate any warning before continuing
9. **Read-back verification — one `queryDocuments` per uploaded or updated document (F73, closes F70's live half too).** An uploader **cannot verify its own work by checking the thing it sent** — on 1PH0 an upload agent ran four separate verifications (line count, byte count, tail match, codepoint grep), every one on the local file on the near side of the API call, reported four documents re-issued and verified, and at least three had not landed. So, per document, after the write: query for a **known distinctive string** from that file (an equation, a paper ref, a worked-example number) and assert it comes back; on the same returned chunk, assert **no heading is empty or parenthetical-only** (the F70 signature). Call shape matters (amended twice in production, 7 Aug 2026 — F73 then F74): scope with **`document_id`**, pass **`min_score: 0.01`** and **`limit: 1`**, and use **no `return_type`** (it collapses to the typed ancestor and returns ~6k tokens; the plain call returns the matched leaf, ~500–800, so a 17-doc wave costs ~15–20k tokens total). Why those values: `min_score` defaults to **0.65**, and a distinctive string can embed below that against its own chunk — the default false-fails an INTACT document (F73) — but **`min_score: 0` is rejected by the search backend** (`x_content_parse_exception`; schema-valid, server-rejected — F74), so 0.01 is the floor: with `document_id` scoping it makes the call a liveness probe, which is what this step is. **Assert on the returned chunk's CONTENT, not on the hit list being non-empty** — at a 0.01 floor a hit is near-guaranteed for any live document, so the information is in the content: the expected string present, callout headings titled (`#### Examiner Tips & Tricks` / `#### Common Error`), no bare `####`, no orphan `(Common Error)`. Targeting an end-of-document callout tests titling and truncation in one call. Scope caveat: `queryDocuments` **cannot see YAML frontmatter** — a green read-back verifies the document's body, never its `subtopic:`/`tags:` lines. **Chunk scope ids: null on the leaf is DESIGNED behaviour, never a defect (F72 — twice concluded broken, twice disproven, most recently 11 Aug 2026 by direct test on a re-issued document).** The plain read-back call returns a `generic` leaf chunk whose `spec_point_id` and `subtopic_id` are both null BY DESIGN: scope lives on the TYPED ancestor chunks Cobalt builds from the document's own `# Sub-topic:` / `## Spec Point:` headings, and binding needs no frontmatter key and no pack action. To see scope bound, pass `return_type: "subtopic"` or `"spec_point"` and read the ancestor's id — one such call per wave is ample if scoping needs demonstrating. **Never assert non-null scope ids on the leaf read-back: that gate would fail every correctly-scoped document in the fleet.** And the F74 meta-rule, earned twice in one day: **a fix to a call specification is verified by issuing the corrected call, not by re-reading the contract it is written against.** **Query phrasing at the 0.01 floor (F73 refinement, 2026-08-10): an ISOLATED bullet string can still rank below an adjacent chunk of its own document** — so include the section-heading text alongside the target string in the query, or raise `limit` and assert the expected string across the top hits rather than only hit 1 (on 4PH1 wave 1 all 16 read-backs verified; three needed the raised-limit path). **A failed read-back means investigate, never re-issue**: try a second distinctive string and a raised `limit` first — the obvious recovery (re-uploading over the live document) is exactly wrong, because `createDocument` twice is forbidden and an `updateDocument` over good content churns every chunk for nothing. **The manifest's verification field is written *from* the read-back, *after* it — by whatever checked, never by whatever wrote.** A manifest field records intent, not delivery. Two API semantics worth knowing so results are read correctly: `updateDocument` chunk churn on a heading change is total by design (chunks are cut at headings, so a changed heading is a deleted-and-recreated chunk — 22/22 on a 22-heading change is correct, not a rewrite); and an update's `N updated` count against a mostly-unchanged document is itself evidence of what had *not* previously landed — zero updated means the content was already live

Close the wave: record final counts in the wave-state file, list any "upstream pack corrections owed" and "prompt hardenings for next wave" at the top — the next wave's `/hero-1-research` gates on that list being applied. Then **write `project.json` → `status`** — `stage`, `units_complete`, `docs_live` (from the manifest), `next_unit`, and every blocker knowingly left open (F30: an empty `blockers` array on a project with a live blocker reads as a checked negative). Also apply the wave-close heuristic: an artifact that is *uniformly* missing across the wave is orchestrator-owed — no agent report can surface it (F29).
